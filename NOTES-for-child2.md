# Child 2a implementation notes

- The public entry point is `caty_gateway.cli:main`; `python -m caty_gateway` uses the same dispatcher. The older gateway module remains a foreground serve alias.
- Non-loopback serve requires a nonblank `CATY_TOKEN` before runtime initialization or socket binding. Empty-token loopback mode retains its legacy behavior.
- Setup and doctor accept `claude`, `codex`, `openclaw`, `hermes`, and `openai-compat`; the underscore spelling is normalized. Codex uses the existing generic CLI preset.
- Doctor performs passive checks only. `--probe` is reserved and exits 2 with a repair hint; no agent prompt is sent.
- Setup renders installed package templates directly and launches the supervisor through `python -m`. Existing service names are preserved: `caty-gateway-<member>.service` on Linux and `ai.caty.gateway.<member>` on macOS.
- Generated environments require authentication, preserve the service executable search path, and default history to the member's state directory. `--no-history` omits the history setting and survives supervisor resume.
- Packaged assets seed a writable member asset directory without replacing existing files. Authenticated health, identity, voice, and QR steps use the generated member token.
- `docs/env.md` is generated by `python tools/env-inventory.py`; run it after source changes. Unknown variables require explicit metadata classification. `make env-check` checks both generated diffs and classification.
- `make test` runs pytest, the scrub audit, and inventory checks. Pytest errors, failed tests, and zero collected tests propagate as failures. `make lint` compiles source and checks inventory.
- The pull-request workflows call the family `ci-v1` workflows. Hosted macOS is intentionally disabled until the public-release follow-up.
- CI bootstraps a venv via `pre_test_setup_ubuntu`; `PYTHON` overrides the interpreter used by `make` (default: `python3`).
- Pairing protocol, HTTP response contracts, privacy documents, and the scrub allowlist are unchanged. External service availability remains an operator prerequisite; tests use passive mocks and local servers.
